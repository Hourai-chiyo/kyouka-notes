## 0. 一页速览

第 4 讲解决了“程序在内存中如何被 CPU 执行”，第 5 讲进一步问：

> 程序平时存在磁盘上，内存容量有限、CPU 只有一个（或少数几个），多个程序、多个用户同时要用计算机——**现代计算机如何管理这些复杂资源，让程序顺利执行？**

主线：

```
存储体系（寄存器 → 缓存 → 内存 → 外存）
        ↓ 容量、速度、价格矛盾
操作系统（资源管理者 + 用户接口 + 虚拟机）
        ↓ 分工 — 合作 — 协同
处理机管理、内存管理、磁盘/文件管理、设备管理、进程管理
        ↓
现代计算机的演变：单机 → 并行/分布式 → 云计算
```

核心结论：

- **存储体系**用“以批量换速度、以空间换时间”解决容量/速度/价格矛盾；
- **操作系统**是管理资源、执行程序的一组程序，核心任务是“把外存上的程序装入内存，并调度 CPU 执行”；
- **程序是文件，进程是装入内存的程序 + 状态信息**；
- 复杂系统的基本思维：**分工、合作、协同**。

## 1. 存储体系与操作系统

### 1.1 回顾：程序如何被执行

第 4 讲的结论：程序装载到内存后，CPU 按 PC 逐条取指执行。

但现代计算机面临的新问题：

- 程序平时存放在**外存**（磁盘、SSD、U 盘等），CPU 不能直接执行外存中的程序；
- 内存容量有限，不能同时装下所有程序和数据；
- CPU 数量有限，多个程序/多个用户如何分配 CPU 时间；
- 内存与外存之间如何自动交换数据。

这些问题由**存储体系 + 操作系统**共同解决。

### 1.2 现代计算机的存储层次

现代计算机不是只有“内存 + 外存”，而是一个多层次存储体系：

| 层次 | 典型部件 | 相对速度（越小越快） | 容量 | 特点 |
|---|---|---|---:|---|
| L0 | 寄存器 | 0.3 ns | 极小 | CPU 内部，最快 |
| L1 | L1 缓存 | 0.9 ns | 很小 | CPU 内部 |
| L2 | L2 缓存 | 3.8 ns | 小 | CPU 内部/近端 |
| L3 | L3 缓存 | 12.9 ns | 较小 | 多核共享 |
| L4 | 内存（RAM） | 50 ns | 中等 | 程序运行时使用 |
| L5 | SSD / 固态硬盘 | 120 ns ~ 150 μs | 大 | 永久存储，速度快 |
| L5 | 机械硬盘 | 约 0.5–50 ms | 很大 | 永久存储，速度慢 |
| L6 | 外部存储（U 盘、光盘、磁带等） | 更慢 | 极大 | 离线/备份 |

> 表中数值取自幻灯片中“华为鲲鹏 820”示例，用于说明数量级差异，不必死记。

存储体系的基本矛盾：

- **快**的存储器**贵**、容量**小**；
- **慢**的存储器**便宜**、容量**大**。

解决策略（幻灯片）：

1. **以批量换速度**：对价格低、存取慢的存储器，一次读取一个**存储块**；
2. **以空间换时间**：用容量较大的慢速存储器保存数据，把当前要用的部分调入快速存储器；
3. **自动管理**：由操作系统/硬件自动完成 CPU—内存—外存之间的信息交换，使外界看起来“容量像外存一样大、速度像内存一样快、价格合理”。

> `[补充]` 这就是**存储层次（memory hierarchy）**和**虚拟存储**的思想：缓存、内存、虚拟内存、磁盘缓存都是同一原则在不同层次上的应用。

### 1.3 内存与外存的区别

| 维度 | 内存 | 外存 |
|---|---|---|
| 读写速度 | 快 | 慢 |
| 容量 | 有限 | 可以很大 |
| CPU 能否直接处理 | 能，按存储单元逐个读写 | 不能，必须先装入内存 |
| 读写单位 | 存储字（存储单元） | 块（若干个扇区/存储字） |
| 断电后内容 | 通常丢失（RAM） | 永久保存 |
| 典型设备 | RAM、ROM | 硬盘、SSD、U 盘、光盘、磁带 |

**课堂多选（不正确的说法）**：

- A 内存读写速度快且容量可以充分大，外存读写速度慢且容量不能太大 —— **错误**（说反了）；
- C CPU 可直接处理外存的数据而无需经过内存 —— **错误**；
- F CPU 通常一个存储字一个存储字地读写外存，而一个块一个块地读写内存 —— **错误**（也说反了）。

答案：**A、C、F**。

### 1.4 磁盘的基本结构

磁盘的物理组织：

- **盘面（surface）**：磁盘有多个盘面，每个盘面有一个读写磁头；
- **磁道（track）/柱面（cylinder）**：盘面上同心圆；
- **扇区（sector）**：磁道被划分成若干扇区，一个扇区通常存放 **512 字节**；
- **磁盘块/簇（cluster）**：若干个连续的扇区，大小随操作系统不同（8、16、64 或更大的 2 的幂）。

磁盘地址：

```
盘号 : 柱面（磁道） : 扇区
```

磁盘读写的三个基本动作：

1. **寻道（seek）**：把读写磁头定位到目标磁道；
2. **旋转（rotate）**：等待目标扇区转到磁头下；
3. **传输（transfer）**：读写数据。

> `[补充]` 机械硬盘的寻道和旋转是主要延迟来源，所以操作系统倾向于“一次读一个块”，以摊销机械动作的开销；SSD 没有机械寻道，但仍有块/页的管理单位。

### 1.5 磁盘容量计算

**课堂练习**：磁盘有 256 个盘面；每个盘面 $2^{16}$ 个磁道；每个磁道 $2^8$ 个扇区；每个扇区 $2^9$ 字节。求容量。

$$
\begin{aligned}
\text{容量} &= 2^8 \times 2^{16} \times 2^8 \times 2^9 \ \text{B} \\
&= 2^{41} \ \text{B} \\
&= 2 \ \text{TB}
\end{aligned}
$$

答案：**A（2 TB = $2^{41}$ B）**。

### 1.6 存储体系概述

```
CPU 寄存器
   ↓
Cache（L1/L2/L3）
   ↓
内存（RAM/ROM）
   ↓ 按存储单元读写
外存（磁盘/SSD/U盘/光盘/磁带）
   ↓ 按块交换
```

- CPU 与内存之间：按**存储单元**读写；
- 内存与外存之间：按**块**交换；
- 这种交换由操作系统自动完成，用户不需要关心。

## 2. 操作系统

### 2.1 操作系统的定义

> **操作系统（Operating System，OS）**：控制和管理计算机系统各种资源（硬件资源、软件资源和信息资源）、合理组织计算机系统工作流程、提供用户与计算机之间接口以解释用户对机器的各种操作需求并完成这些操作的一组程序集合，是最基本、最重要的系统软件。

三个作用：

1. **资源管理者**：管理 CPU、内存、外存、设备、文件等资源；
2. **虚拟机**：为用户提供一个抽象、方便的计算机，隐藏硬件细节；
3. **用户与硬件之间的接口**：用户通过操作系统使用硬件。

> `[补充]` 可以把操作系统理解为“硬件之上的一层软件抽象”：应用程序不需要直接操作磁盘、内存、CPU 寄存器，而是通过操作系统提供的系统调用完成工作。

### 2.2 操作系统要解决的根本问题

幻灯片列出的四个问题：

1. 程序如何被 CPU 执行？CPU 执行哪个程序？
2. 程序如何装载到内存中？装载到哪里？
3. 程序如何存储在外存上面？
4. CPU、内存、外存之间如何协同工作？

对应操作系统的主要功能：

| 功能 | 管理对象 | 主要任务 |
|---|---|---|
| 处理机管理 | CPU | 调度哪个进程/程序占用 CPU |
| 内存管理 | 内存 | 分配、回收、地址转换、虚拟内存 |
| 磁盘与文件管理 | 外存 | 文件组织、目录、FAT、读写 |
| 设备管理 | 各种 I/O 设备 | 设备驱动、缓冲、分配 |
| 作业与进程管理 | 程序/进程 | 作业调度、进程创建/切换/同步 |
| 网络管理 | 网络资源 | 连接、协议、通信 |

### 2.3 理解复杂操作系统的基本思维：分工—合作—协同

| 层次 | 含义 |
|---|---|
| **分工** | 各部件独立管理自己的具体任务（小粒度工作） |
| **合作** | 把宏观作业分解为任务，调度各部件执行 |
| **协同** | 合作的自动化与高效率 |

操作系统本身就是这样构造出来的：

1. **分工**：处理机管理、内存管理、磁盘管理……各自独立管理一个部件；
2. **合作**：以“让 CPU 执行外存上的程序”为中心任务，各部件合作；
3. **协同**：解决合作中的同步、自动化、最优化问题。

> `[补充]` 这也是软件工程中“分而治之 + 模块化 + 接口协作”的思想。操作系统是这种思想最复杂的实例之一。

### 2.4 磁盘与文件管理：化整为零，还零为整

文件在磁盘上不是连续存放的，而是被拆成若干**簇/块**分散存放：

```
文件 A → 簇 17 → 簇 26 → 簇 24 → 簇 32 → ... → End
```

需要解决三个问题：

1. 确定零存空间的大小（簇/块的大小）；
2. 分解、编号及次序：在哪里、怎样保存“下一块在哪里”的信息；
3. 能否自动化。

#### 文件分配表（FAT）

- 为每个簇/块设置一个表项；
- 表项的值 = 该簇的**下一簇编号**；
- 文件目录中保存文件名和**起始簇号**；
- 顺着 FAT 链就能读出整个文件。

例：

```
文件 A —— 17
FAT:
17 → 26
26 → 24
24 → 32
32 → 44
44 → 55
55 → 47
47 → End
```

#### 磁盘的四个主要区域

1. **保留扇区**：系统引导、逻辑分区等；
2. **文件分配表区域**：FAT（NTFS 中为 MFT，主文件表）；
3. **根目录区域**：文件夹/目录；
4. **数据区域**：文件内容。

#### 文件读写过程

- 打开文件：从目录找到起始簇号；
- 读文件：按 FAT 链逐簇读取，直到 End；
- 写文件：找空闲簇，修改 FAT 链和目录项。

**课堂练习**：一簇 = 4 KB（8 个扇区），FAT 表项数为 $2^{20}$，能管理的磁盘空间是多少？

$$
2^{20} \times 4\ \text{KB} = 2^{20} \times 2^2\ \text{KB} = 2^{22}\ \text{KB}
$$

答案：**C（$2^{22}$ KB）**。

### 2.5 内存管理

- 内存被划分为**页（page）**；
- 通常内存的一页与磁盘的一块/簇大小相等，便于换入换出；
- 程序运行时不需要全部装入内存，可以按页调入（虚拟内存）；
- 操作系统负责页面的分配、回收、替换和地址转换。

> `[补充]` 虚拟内存的关键：程序使用的是**虚拟地址**，由硬件（MMU）和操作系统页表转换为**物理地址**；缺页时从外存调入。这使“小内存运行大程序”成为可能。

### 2.6 处理机管理与分时

CPU 的一种运用方式：**分时（time-sharing）**。

- 一台主机、一个 CPU，执行多个程序（来自多个用户的多个终端）；
- 操作系统维护一个**时间轮盘**；
- 按时间片轮流让 CPU 执行不同程序；
- 时间片足够小，每个用户都感觉自己独占 CPU。

> `[补充]` 分时系统是“并发”的典型实现：宏观上多个程序同时运行，微观上 CPU 在它们之间快速切换。现代操作系统还使用优先级、多级反馈队列等调度策略。

### 2.7 程序与进程

| 概念 | 定义 | 存放位置 |
|---|---|---|
| **程序（文件）** | 存储在磁盘上的程序文件 | 外存 |
| **进程** | 装入内存中的程序，还包括程序装载和运行相关的状态信息 | 内存 |

要点：

- 一个程序文件可以产生**多个进程**；
- 进程除了可执行的程序代码外，还包括状态描述信息（如 PC、寄存器、内存映射、打开的文件等），由操作系统管理；
- 操作系统本身也有进程，也需要被调度执行；
- CPU 在操作系统进程和应用程序进程之间来回切换。

**课堂练习 1**：关于“程序”与“进程”，不正确的是？

- A 不管是“程序”还是“进程”，都是指可以被执行的程序代码 —— **错误**（进程还包括状态信息）；
- 答案：**A**。

**课堂练习 2**：关于“操作系统”和“应用程序”，不正确的是？

- C 操作系统自身的进程，不由操作系统调度和执行；操作系统仅管理应用程序的进程 —— **错误**（操作系统进程也要被调度）；
- 答案：**C**。

### 2.8 典型计算机系统的启动与工作过程

```
电源接通
   ↓ ①
CPU 执行 ROM 中的启动程序
   ↓ ②
从外存读取操作系统
   ↓ ③
操作系统装入内存并开始管理
   ↓
操作系统调度 CPU 执行应用程序/数据
```

roughly：

```
电源 → ROM 程序 → CPU → ROM 中的程序 → 操作系统/应用程序/数据
                         ↑
                    外存储器
```

> `[补充]` 这就是“引导（boot）”过程：BIOS/UEFI → 引导加载程序 → 操作系统内核 → 用户程序。

### 2.9 操作系统的理解（课堂多选）

下列说法正确的有：

- A 计算资源的管理者（硬件像仓库，OS 像仓库管理员）；
- B 计算资源的调度者和执行者（硬件像士兵，OS 像指挥员）；
- C 功能更丰富、用户更容易使用的计算机（硬件是基本功能，OS 组合出更强功能）；
- D 人与机器的接口（封装硬件功能，用户通过 OS 使用硬件）。

答案：**A、B、C、D**（都是对操作系统的合理理解）。

**“操作系统最核心最基本的功能”**：将外存的程序装载入内存，并调度 CPU 完成程序的执行（**B**）。

## 3. 现代计算机的演变

### 3.1 冯·诺伊曼计算机

单机结构：

```
CPU（运算器 + 控制器）
内存
外存
```

程序和数据装入内存，CPU 按 PC 逐条执行。

### 3.2 并行与分布式

- **一台主机多个 CPU 执行一个程序**：并行计算；
- **多台计算机通过网络协同**：分布式计算；
- 客户端（个人计算设备）+ 网络（局域网/广域网）+ 服务器端（多机并行、服务器端操作系统、中间件、CPU、磁盘阵列）。

```
User1 ... Usern
   ↓ 客户端应用软件
个人计算设备
   ↓ 广域网/局域网
服务器端应用软件
中间件
多机并行 — 服务器端操作系统
CPU / 磁盘阵列
```

### 3.3 云计算

- 用户通过个人计算机和网络访问“云”中的软件、存储和计算资源；
- 服务器端由多机并行、服务型操作系统、中间件支撑；
- 用户不需要关心底层硬件的位置和规模。

关于云的常见说法（课堂练习）：

- A 普通人可以把照片、视频等放入“云”，实现任何时间、地点、任何人的访问 —— 正确；
- B “云是安全的、可靠的，而云也确实是安全的、可靠的” —— 绝对化的说法，**不正确**（云服务仍需考虑安全、隐私、可靠性风险）；
- C 普通人可以利用云建立庞大数据库，突破个人计算机容量限制 —— 正确。

答案：**B**。

> `[补充]` 云计算的本质是**资源池化 + 按需分配 + 网络访问**；它并不是“绝对安全”的同义词，安全责任通常由云服务商和用户共同承担。

## 4. 附：第 6 讲开头（计算机语言的发展）

### 4.1 算法、语言与程序

```
解决问题的步骤（算法）
        ↓ 用人和计算机都能理解的语言书写
计算机语言（语法要素、规范、标准）
        ↓
程序（计算机能理解并执行的步骤）
```

学习路径：

- 读算法、写算法；
- 算法设计策略、算法分析方法、数据结构设计、算法表达方法；
- 高级语言语法要素、程序设计技巧、程序设计环境；
- 读程序、写程序。

### 4.2 计算机语言的发展阶段

| 阶段 | 编写单位 | 转换程序 | 特点 |
|---|---|---|---|
| 机器语言 | 指令（0/1 编码） | 无 | CPU 直接执行，人难读难写 |
| 汇编语言 | 指令（助记符） | 汇编程序 | 与机器指令一一对应，仍依赖机器 |
| 高级语言 | 语句 | 编译程序 | 接近自然语言，机器无关性 |
| 面向对象/可视化语言 | 对象（类）、控件、事件 | 编译器/解释器 | 像搭积木一样构造程序 |

核心权衡：

- 越高级的语言，**编程效率越高**，但**执行效率可能越低**；
- 越底层的语言，**执行效率越高**，但**编程效率越低**。

**课堂练习**：从机器语言到高级语言再到对象化语言，正确的是？
- **C：编程效率越来越高，程序执行效率可能越来越低。**

### 4.3 汇编语言与高级语言

- **汇编语言**：用助记符书写程序，与机器指令一一对应；由**汇编程序**翻译成机器语言。
- **高级语言**：用类似自然语言的语句书写程序；由**编译程序**翻译成机器语言。
- 高级语言具有**机器无关性**；一条高级语言语句往往对应若干条机器指令，不要求一一对应。

**课堂练习**：关于汇编语言程序，正确的是？
- **B：汇编程序是将汇编语言源程序转换成机器程序的程序。**

### 4.4 高级语言程序的阅读

阅读高级语言程序的基本步骤：

1. 识别**标识符**（常量、变量）；
2. 识别**表达式**（算术、比较、逻辑），不管多复杂，结果都是一个值；
3. 识别**语句**（赋值、分支、循环）；
4. 识别**函数及其调用**。

面向对象/可视化程序还要识别：

1. 对象（窗体、控件）；
2. 对象的属性；
3. 对象的控制操作（消息与事件：单击、双击、获得焦点、文本变化等）；
4. 事件驱动程序；
5. 对象及程序的控制逻辑。

### 4.5 高级语言程序的基本要素（衔接第 6 讲）

- 常量、变量与表达式：
  - 算术表达式 → 数值；
  - 比较表达式 → 真/假；
  - 逻辑表达式 → 真/假；
- 赋值语句；
- 分支语句（If）；
- 循环语句（While/For）；
- 函数及其调用。

> 详细讲解见《第06讲 由机器语言到高级语言》。

### 5.3 自测问题（附答案）

1. 为什么需要存储体系？
   **答**：单一存储器无法同时满足速度快、容量大、价格低；用多层次结构把快的和慢的、贵的和便宜的组合起来，自动管理，使整体接近“快、大、便宜”。
2. 内存和外存的分工是什么？
   **答**：内存快但容量有限，存放当前运行的程序和数据；外存慢但容量大，永久保存程序和数据；CPU 不能直接处理外存，需先装入内存。
3. 磁盘地址由哪几部分组成？扇区和簇有什么区别？
   **答**：盘号:柱面(磁道):扇区；扇区是磁盘读写的基本单位（通常 512 B），簇/块是若干个连续扇区，是文件分配的单位。
4. FAT 的作用是什么？
   **答**：为每个簇记录下一簇的编号，把分散的簇串成文件链；目录记录文件名和起始簇号。
5. 程序和进程有什么区别？
   **答**：程序是外存上的静态文件；进程是装入内存的程序加上运行状态信息，是动态的执行实例；一个程序可产生多个进程。
6. 操作系统的基本功能有哪些？
   **答**：处理机管理、内存管理、磁盘/文件管理、设备管理、作业与进程管理、网络管理等。
7. 分时系统如何让多个用户“感觉独占 CPU”？
   **答**：操作系统按时间片轮流调度，时间片足够小，用户感觉不到切换。
8. 机器语言、汇编语言、高级语言各有什么优缺点？
   **答**：机器语言执行效率最高但难写难读；汇编语言用助记符、与机器指令一一对应，仍依赖机器；高级语言接近自然语言、编程效率高、机器无关，但执行效率可能较低。
