## 0. 一页速览

第 4 讲讲“机器程序如何执行”，第 5 讲讲“操作系统如何管理资源”，第 6 讲回答：

> **人如何用接近自然语言的方式写程序，机器又如何把高级语言程序变成可执行的机器指令？**

主线：

```
机器语言（0/1 指令）
   ↓ 用助记符代替 0/1
汇编语言（助记符）——汇编程序——→ 机器语言
   ↓ 用语句代替指令
高级语言（语句）——编译程序——→ 机器语言
   ↓ 用对象/控件代替语句
面向对象/可视化语言——编译器/解释器——→ 机器语言
```

核心结论：

- 语言越高级，**编程效率越高**，但**执行效率可能越低**；
- 高级语言程序的基本要素：**常量/变量、表达式、语句（赋值/分支/循环）、函数**；
- 不同语言（C、Python、Visual Basic）**基本要素相同，语法不同**；
- 程序构造的方法：**自顶向下、逐步细化**，先流程图后代码；
- 程序执行前要经过**编辑 → 编译 → 链接 → 执行**（或解释执行）。

## 1. 计算机语言的发展

### 1.1 算法、计算机语言与程序

```
解决问题的步骤（算法）
        ↓ 用人和计算机都能理解的语言书写
计算机语言（语法要素、规范、标准）
        ↓
程序（计算机能理解并执行的步骤）
```

学习路径：

- **读算法、写算法**：算法设计策略、算法分析方法、数据结构设计、算法表达方法；
- **读程序、写程序**：高级语言语法要素、程序设计技巧、程序设计环境。

### 1.2 机器语言

> **机器语言**：用二进制和编码方式提供的指令系统所编写程序的语言。

- 指令系统：CPU 用二进制和编码提供的、可以解释并执行的命令的集合；
- 所有程序最终都要转换成机器程序，计算机才能执行；
- 机器语言程序由一条条指令组成，指令 = 操作码 + 地址码。

例：计算 $7+10$ 并存储的机器程序（示意）：

```
100001 10 00000111    ; 取数 7
100010 10 00001010    ; 加 10
100101 11 00000110    ; 存结果
111101 00             ; 停机
```

机器语言的缺点：**人难读、难写、难调试**。

### 1.3 汇编语言

> **汇编语言**：用助记符书写程序的语言，与机器语言一一对应。

- 用符号（助记符）代替 0/1 操作码；
- 需要**汇编程序**把汇编语言源程序翻译成机器语言程序；
- 汇编语言仍依赖具体机器（机器相关）。

例：计算 $7+10$ 并存储的汇编语言源程序：

```asm
MOV A, 7
ADD A, 10
MOV (6), A
HLT
```

翻译过程：

```
汇编语言源程序（助记符）
        ↓ 汇编程序（转换规则：助记符 → 机器指令）
机器语言程序（0/1 编码）
```

**课堂练习**：关于汇编语言程序，下列说法正确的是？

- A 汇编程序是用汇编语言编写的程序 —— 错误（汇编语言写的叫“汇编语言源程序”）；
- B 汇编程序是将汇编语言源程序转换成机器程序的程序 —— **正确**；
- C 汇编程序是能够被机器直接执行的程序 —— 错误；
- D 汇编程序是用助记符等编写的程序 —— 错误。

答案：**B**。

### 1.4 高级语言

> **高级语言**：用类似自然语言的语句编写程序的语言。

- **高级语言源程序**：用高级语言编写的程序；
- **编译程序（编译器）**：把高级语言源程序翻译成机器语言程序的程序；
- 高级语言具有**机器无关性**：同一条语句可以在不同机器上编译执行；
- 一条高级语言语句往往对应若干条机器指令，**不要求一一对应**。

例：计算 $7+10$ 并存储：

```c
Result = 7 + 10;
return;
```

### 1.5 语言发展的基本思维：更大的“积木块”

```
CPU 能识别与执行的机器指令
        ↑ 汇编程序
汇编语言源程序（助记符积木块）
        ↑ 编译程序
高级语言源程序（语句积木块）
        ↑ 编译器
面向对象/可视化程序（对象积木块）
```

核心权衡：

- 越高级的语言，**编程效率越高**，但**执行效率可能越低**；
- 越底层的语言，**执行效率越高**，但**编程效率越低**。

**课堂练习**：从机器语言到高级语言再到对象化编程语言，下列说法正确的是？

- A 编程效率越来越高，程序执行效率越来越高 —— 不一定；
- B 编程效率可能越来越低，程序执行效率越来越高 —— 错误；
- C 编程效率越来越高，程序执行效率可能越来越低 —— **正确**；
- D 两者都可能越来越低 —— 错误。

答案：**C**。

### 1.6 多种高级语言

幻灯片列出的语言谱系：

```
FORTRAN、ALGOL、BASIC、PASCAL、C、C++、Java、
Python、JavaScript、Perl、Visual BASIC、Delphi、Smalltalk、Simula……
```

语言是不断演化的：从面向过程 → 面向对象 → 可视化/积木式 → 领域专用语言/智能化语言。

> `[补充]` 语言没有绝对优劣，只有适用场景：C 适合底层/性能敏感场景，Python 适合快速开发/数据分析，Java 适合大型工程，SQL 适合数据库查询。

## 2. 高级语言程序的基本要素

### 2.1 常量、变量与表达式

#### 算术表达式

结果是一个**数值**：

```c
A1 + (B2 - x1 + 76) * 3
(B2 + yy4) / L3 - xx3
```

#### 比较表达式

结果是逻辑“真”或“假”：

```c
Grade < 90
Grade >= 70
N4 < A1 + B2 + 20
```

注：`A1 + B2 + 20` 是算术表达式，先算出数值，再与 `N4` 比较。

#### 逻辑表达式

结果也是“真”或“假”：

```c
(x1 >= A1) && (B2 <> y2)
```

常用逻辑运算：

| 运算 | 常见写法 | 含义 |
|---|---|---|
| 与 | `AND`、`&&` | 都为真才为真 |
| 或 | `OR`、`||` | 有一个为真就为真 |
| 非 | `NOT`、`!` | 取反 |
| 不等 | `<>`、`!=` | 不相等 |

> `[补充]` 表达式的求值有优先级：一般算术 > 比较 > 逻辑；不确定时加括号。不同语言的运算符写法不同（如 `&&`/`AND`、`<>`/`!=`），但语义相同。

### 2.2 赋值语句

把表达式的计算结果赋给一个变量：

```c
M = X > Y + 50;
M = (X > Y) AND (X < Y);
K = K + (5 * K);
```

注意：

- `=` 是赋值，不是数学上的等号；
- `K = K + (5 * K)` 表示“取出 K 的旧值，计算后写回 K”；
- 赋值号两边类型要匹配。

### 2.3 分支语句

基本形式：

```c
If (条件表达式)
{ 条件为真时执行的语句序列 }
Else
{ 条件为假时执行的语句序列 }
```

例：

```c
Y = 50;
Z = 80;
X = 30;
X = Z + Y;
If (Y > Z) {
    X = X - Y;
} Else {
    X = X - Z;
}
X = X + Y;
If (X > Z) { X = Y; }
X = X - Z;
If (X > Y) { X = X - Y; }
```

执行时根据条件选择一条分支，另一条不执行。

### 2.4 循环语句

#### Do-While（先执行，后判断）

```c
X = 1;
Y = 2;
Sum = 0;
Do {
    Sum = X + Y;
    X = X + 1;
    Y = Y + 1;
} While (Sum <= 10);
```

特点：**循环体至少执行一次**，然后判断条件，条件为真继续循环。

#### While（先判断，后执行）

```c
X = 1;
Y = 2;
Sum = 0;
While (Sum < 0) {
    Sum = X + Y;
    X = X + 1;
    Y = Y + 1;
}
```

特点：**先判断条件**，条件为假时循环体一次也不执行。

> `[补充]` 两种循环可以互相转换，但要注意“至少执行一次”和“可能一次都不执行”的区别。实际编程中还要保证循环能终止（循环变量最终使条件为假）。

### 2.5 函数

> **函数**：一种抽象，用一个名字代表一个程序段落。

组成：

- **函数名**：抽象出来的名字；
- **形式参数**：函数定义中使用的参数，调用时被实际参数替换；
- **函数体**：实现函数功能的语句序列；
- **返回值**：函数计算的结果（可有可无）。

例：

```c
Main()
{
    Printf("请输入被加数");
    Scanf("%d", &x);
    Printf("请输入加数");
    Scanf("%d", &y);
    z = Sum(x, y);       // 函数调用，x、y 是实际参数
    Printf("求和结果为%d", z);
}

Sum(a, b)                // a、b 是形式参数
{
    return a + b;        // 函数体
}
```

函数的好处：

- **抽象**：调用者只需知道“函数做什么”，不必关心“怎么做”；
- **复用**：同一函数可以在多处调用；
- **分解**：把大程序分解成小函数，便于设计和调试。

### 2.6 基本要素总结

| 要素 | 作用 | 例子 |
|---|---|---|
| 常量、变量 | 表示数据 | `X = 21;` |
| 表达式 | 计算一个值 | `A1 + (B2 - x1 + 76) * 3` |
| 赋值语句 | 把值写入变量 | `K = K + 5;` |
| 分支语句 | 根据条件选择执行 | `If ... Else ...` |
| 循环语句 | 重复执行 | `While`、`Do-While`、`For` |
| 函数 | 抽象与复用程序段 | `Sum(x, y)` |

**课堂练习 1**：关于普通计算机语言（程序）的基本构成要素，最完整的是？

- A 常量与变量和表达式；
- B 常量与变量、表达式和语句；
- C 常量与变量、表达式、语句和函数；
- D 都不完整。

答案：**C**。

**课堂练习 2**：程序行 (60) 执行了多少次？

```basic
(10) N = 6;
(20) X = 0;
(30) Y = 1;
(40) For I = 1 To N-1 Step 1
(50) Z = X + Y;
(60) X = Y;
(70) Y = Z;
(80) Next I
```

- 循环变量 `I` 从 1 到 $N-1 = 5$，步长 1；
- 共执行 5 次；
- 答案：**B（5）**。

## 3. 不同计算机语言的异同点

### 3.1 C 语言与 Python 的冒泡排序

C 语言版本：

```c
void bubble_sort(int *lists, int count)
{
    int i, j;
    for (i = 0; i < count - 1; i++)
    {
        for (j = 0; j < count - i - 1; j++)
        {
            if (lists[j] < lists[j + 1])
            {
                int k = lists[j];
                lists[j] = lists[j + 1];
                lists[j + 1] = k;
            }
        }
    }
}
```

Python 版本（示意）：

```python
def bubble_sort(lists, count):
    for i in range(0, count):
        for j in range(0, count - 1 - i):
            if lists[j] < lists[j + 1]:
                k = lists[j]
                lists[j] = lists[j + 1]
                lists[j + 1] = k
    return lists
```

### 3.2 相同点与不同点

**相同的基本要素**：

- 常量、变量；
- 表达式（算术、比较、逻辑）；
- 赋值语句；
- 分支结构、循环结构、顺序结构；
- 函数。

**不同点**：

- 语法形式不同（括号、缩进、关键字、运算符）；
- 类型系统不同（C 需要声明类型，Python 动态类型）；
- 执行方式不同（C 编译执行，Python 解释执行）；
- 库和运行环境不同。

> `[补充]` 学习新语言时，抓住“基本要素”的对应关系，比死记语法更有效。例如：C 的 `for (i=0; i<n; i++)` 对应 Python 的 `for i in range(n)`。

## 4. 用高级语言构造程序

### 4.1 示例：1000 瓶啤酒问题

**题目**：有 1000 瓶啤酒，每喝完一瓶得到一个空瓶子，每 3 个空瓶子又能换 1 瓶啤酒，喝掉以后又得到一个空瓶子。问总共能喝多少瓶啤酒？还剩多少空瓶子？

#### 分析

- 初始：`BeerBottle = 1000`（啤酒总数），`EmptyBottle = 0`（空瓶数）；
- 每喝一瓶：`EmptyBottle + 1`；
- 若空瓶数达到 3：换 1 瓶啤酒，`BeerBottle + 1`，`EmptyBottle = 0`；
- 循环直到所有啤酒喝完；
- 最后若剩 2 个空瓶，可以向老板**借 1 个空瓶**，凑 3 个换 1 瓶，喝完把空瓶还回去。

#### 流程图（简化）

```
开始
  BeerBottle = 1000
  EmptyBottle = 0
  i = 0
  ↓
喝一瓶：EmptyBottle = EmptyBottle + 1
  ↓
EmptyBottle == 3?
  ├─ 是 → BeerBottle = BeerBottle + 1
  │        EmptyBottle = 0
  └─ 否 → i = i + 1
  ↓
i < BeerBottle?
  ├─ 是 → 回到“喝一瓶”
  └─ 否 → EmptyBottle == 2?
             ├─ 是 → 借 1 瓶：BeerBottle + 1，EmptyBottle = 0
             └─ 否 → 输出 BeerBottle 和 EmptyBottle
  ↓
结束
```

#### 代码（示意）

```c
int HowMuchBeer()
{
    int BeerBottle = 1000;
    int EmptyBottle = 0;

    for (i = 0; i <= BeerBottle; i++)
    {
        EmptyBottle = EmptyBottle + 1;
        if (EmptyBottle == 3)
        {
            BeerBottle = BeerBottle + 1;
            EmptyBottle = 0;
        }
    }

    // 最后剩 2 个空瓶时，向老板借 1 个空瓶，换 1 瓶，喝完还回空瓶
    if (EmptyBottle == 2)
    {
        BeerBottle = BeerBottle + 1;
        EmptyBottle = 0;
    }

    Printf("EmptyBottle=%d", EmptyBottle);
    Printf("BeerBottle=%d", BeerBottle);
}
```

#### 结果

- 不借空瓶：喝 **1499** 瓶，剩 **2** 个空瓶；
- 借 1 个空瓶再还：喝 **1500** 瓶，剩 **0** 个空瓶。

> `[补充]` 为什么是 1499？每换 1 瓶，空瓶净减少 2 个（3 个换出去，喝完又得 1 个）。1000 个空瓶最多换 $\lfloor (1000-1)/2 \rfloor = 499$ 瓶，最后剩 2 个空瓶。总数 $1000+499=1499$。借 1 个后还能再换 1 瓶，所以 1500。

### 4.2 程序构造的基本方法

1. **理解问题**：明确输入、输出、约束；
2. **设计算法**：用自然语言/流程图描述步骤；
3. **逐步细化**：把大步骤分解成小步骤；
4. **编写代码**：把流程图翻译成高级语言；
5. **测试与调试**：用典型数据验证结果。

> `[补充]` 这就是“自顶向下、逐步细化”的结构化程序设计方法。流程图是算法与代码之间的桥梁。

### 4.3 课堂练习：循环与数组

**练习 1**：读程序，判断功能。

```basic
(10) main()
(20) { int counter;
(30) ... // 输入 N 值的语句，略
(40) long product = 1;
(50) for counter = 1 to N step 2
(60) { product = product * counter; }
(70) return product;
(80) }
```

- `counter` 取 1, 3, 5, …；
- `product = 1 × 3 × 5 × … × (N-1)`；
- 答案：**C**。

**练习 2**：程序行 (60) 执行 3 次后，`product` 和 `counter` 的值？

- 第 1 次：`counter=1`，`product=1`；
- 第 2 次：`counter=3`，`product=3`；
- 第 3 次：`counter=5`，`product=15`；
- 循环下一次 `counter` 变为 7；
- 答案：**B（15, 7）**。

**练习 3**：已知矩阵 $M$：

```
       0   1   2   3
0     11  25  22  25
1     45  39   8  44
2     21  28   0 100
3     34  83  75  16
```

```basic
(10) int I = 2, J;
(20) int Sum1 = 0, Sum2 = 0;
(30) For J = 0 to 3 Step 1
(40) { Sum1 = Sum1 + M[I][J];
(50)   Sum2 = Sum2 + M[J][I]; }
```

- `Sum1` = 第 2 行之和 = 21 + 28 + 0 + 100 = **149**；
- `Sum2` = 第 2 列之和 = 22 + 8 + 0 + 75 = **105**；
- 答案：**C（149, 105）**。

**练习 4**：另一个矩阵求和程序：

```basic
(10) int J;
(20) int Sum1 = 0, Sum2 = 0;
(30) For J = 0 to 3 Step 1
(40) { Sum1 = Sum1 + M[J][J];
(50)   Sum2 = Sum2 + M[3-J][J]; }
```

- `Sum1` = 主对角线 = 11 + 39 + 0 + 16 = **66**；
- `Sum2` = 副对角线 = 34 + 28 + 8 + 25 = **95**；
- 答案：**D（66, 95）**。

## 5. 程序设计过程与程序设计环境

### 5.1 程序设计过程

以 C 语言为例：

```
编辑源程序（.c）
        ↓
编译（compiler）
        ↓
目标文件（.o/.obj）
        ↓
链接（linker，链接库函数）
        ↓
可执行文件（.exe/ELF）
        ↓
装入内存、执行
```

- **编辑**：用编辑器写源代码；
- **编译**：把高级语言源程序翻译成机器指令（目标代码）；
- **链接**：把目标文件与库函数、其他目标文件组合成可执行文件；
- **执行**：操作系统把可执行文件装入内存，CPU 执行。

> `[补充]` 解释型语言（如 Python）没有显式的“编译—链接”步骤，而是由解释器逐行解释执行；但底层仍然要转换成机器能执行的指令。Java 则先编译成字节码，再由 JVM 解释/JIT 编译执行。

### 5.2 程序设计环境

常见的程序设计环境：

- 编辑器 + 编译器 + 调试器（如 GCC + GDB）；
- 集成开发环境（IDE，如 Visual Studio、PyCharm、CLion）；
- 在线编程平台；
- 版本控制、构建工具、测试框架。

### 6.1 算法概述

- 算法是“计算机与软件的灵魂”；
- 算法是求解问题的一系列步骤；
- 算法的基本性质：有穷性、确定性、可行性、输入、输出；
- “是否会编程序”，本质上是“能否想出求解问题的算法”。

### 6.2 问题与数学建模

- 哥尼斯堡七桥问题 → 图论模型；
- TSP（旅行商问题）→ 图上的最短哈密顿回路；
- 建模就是把现实问题抽象成数学/数据结构问题。

### 6.3 算法策略

- 遍历/枚举：列出所有可能路线，选最优；
- 贪心：每一步做当前最好的选择；
- 动态规划、分治、回溯等（后续/其他课程展开）。

### 6.4 算法的表达

- 数据结构：变量、数组、树、图；
- 控制结构：顺序、分支、循环；
- 表达工具：自然语言、流程图、伪代码、程序。

### 6.5 算法复杂性与计算复杂性

- 时间复杂度、空间复杂度；
- 大 $O$ 记号；
- 多项式时间 $O(n^k)$ 与指数时间 $O(2^n)$、阶乘时间 $O(n!)$；
- P 类问题 vs. NP 类问题；
- TSP 的遍历算法复杂度 $O((n-1)!)$，规模稍大就不可行。

### 7.3 自测问题（附答案）

1. 机器语言、汇编语言、高级语言有什么区别？
   **答**：机器语言是 0/1 指令，机器直接执行；汇编语言用助记符，与机器指令一一对应，需汇编程序翻译；高级语言用语句，机器无关，需编译/解释程序翻译。
2. 汇编程序和汇编语言源程序有什么区别？
   **答**：汇编语言源程序是用汇编语言写的程序；汇编程序是把汇编语言源程序翻译成机器程序的翻译程序。
3. 高级语言程序的基本要素有哪些？
   **答**：常量/变量、表达式、赋值语句、分支语句、循环语句、函数。
4. `While` 循环和 `Do-While` 循环有什么区别？
   **答**：`While` 先判断后执行，可能一次都不执行；`Do-While` 先执行后判断，至少执行一次。
5. 函数的形式参数和实际参数有什么区别？
   **答**：形式参数是函数定义中的参数，实际参数是调用时传入的具体值；调用时用实际参数替换形式参数。
6. 程序设计的四个基本步骤是什么？
   **答**：理解问题、设计算法、编写代码、测试调试（可细化为编辑→编译→链接→执行）。
7. 1000 瓶啤酒、3 个空瓶换 1 瓶，最后能喝多少瓶？
   **答**：不借空瓶 1499 瓶、剩 2 个空瓶；借 1 个空瓶再还，1500 瓶、剩 0 个空瓶。
