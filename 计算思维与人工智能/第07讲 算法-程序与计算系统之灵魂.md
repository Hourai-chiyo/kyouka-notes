## 1. 算法概述

### 1.1 什么是算法

- “算法”（Algorithm）一词源于阿拉伯数学家阿科瓦里茨米（Al-Khowarizmi），公元 825 年《波斯教科书》中概括了四则算术运算的计算规则。
- **算法**：一个有穷规则的集合，它用规则规定了解决某一特定类型问题的运算序列，或者规定了任务执行/问题求解的一系列步骤。

广义上，乐谱、太极拳谱都可以看作“算法”。

### 1.2 算法示例：欧几里得算法（求最大公约数）

输入：正整数 $M$、$N$（设 $M > N$）
输出：$M$ 和 $N$ 的最大公约数

算法步骤：

```
Step 1. M 除以 N，记余数为 R。
Step 2. 如果 R ≠ 0：
            将 N 的值赋给 M，R 的值赋给 N，返回 Step 1；
        否则：
            最大公约数是 N，输出 N，算法结束。
```

模拟执行：

| 问题 | M | N | R | 最大公约数 |
|---|---:|---:|---:|---:|
| 具体问题 1 | 32 | 24 | | ? |
| 第 1 步 | 32 | 24 | 8 | |
| 第 2 步 | 24 | 8 | 0 | **8** |
| 具体问题 2 | 31 | 11 | | ? |
| 第 1 步 | 31 | 11 | 9 | |
| 第 2 步 | 11 | 9 | 2 | |
| 第 3 步 | 9 | 2 | 1 | |
| 第 4 步 | 2 | 1 | 0 | **1** |

> `[补充]` 欧几里得算法是“迭代”的典型：每一步用“较大数除以较小数取余”，直到余数为 0。它只用到除法、赋值、逻辑判断三种基本运算。

### 1.3 算法的五个特征

| 特征 | 含义 |
|---|---|
| **有穷性** | 一个算法在执行有穷步规则之后必须结束 |
| **确定性** | 算法的每一个步骤必须确切定义，不得有歧义 |
| **输入** | 算法有零个或多个输入 |
| **输出** | 算法有一个或多个输出/结果 |
| **能行性** | 算法中的运算和操作必须是基本的，能由机器自动完成，并在有限时间内完成 |

**课堂练习 1**：关于算法的命题，不正确的是？

- A 算法规定了任务执行/问题求解的一系列、有限的步骤 —— 正确；
- B 算法所规定的计算/处理步骤是有限的，但算法实际执行的计算/处理步骤可以是无限的 —— **错误**（违反有穷性）；
- C 算法可以没有输入，但必须有输出 —— 正确；
- D 每一步必须确切定义，运算和操作必须基本、可由机器自动完成 —— 正确。

答案：**B**。

**课堂练习 2**：关于算法与程序、计算机语言之间的关系，不正确的是？

- A 算法是解决问题的步骤，同一个问题可能有多个算法 —— 正确；
- B 算法不能直接由计算机执行，必须转换为程序才能执行 —— 正确；
- C 算法只能由高级语言实现，不能通过机器语言实现 —— **错误**；
- D 求解问题的多个算法不一定获得相同的解 —— 正确（精确解/近似解可能不同）。

答案：**C**。

## 2. 问题与数学建模

### 2.1 数学建模

> **数学建模**：用数学语言描述实际现象的过程，即建立数学模型的过程。
>
> **数学模型**：对实际问题的一种数学表述，是关于部分现实世界为某种目的的一个抽象的、简化的数学结构。

算法类问题需要数学建模，而数学建模能发现问题的本质。

### 2.2 哥尼斯堡七桥问题

问题：寻找走遍这 7 座桥且只许走过每座桥一次、最后又回到原出发点的路径。

建模：

- **陆地 → 节点**；
- **连接陆地的桥梁 → 连接节点的边**；
- 问题转化为：在一个图中，寻找经过每条边一次且仅一次的**回路**。

结论：

- 如果从某节点出发又回到该节点，那么连接该节点的边数应当是**偶数**（每进一次就要出一次）；
- 哥尼斯堡七桥问题的四个陆地节点度数都是奇数，所以**无解**。

### 2.3 图论中的相关概念

| 概念 | 含义 |
|---|---|
| 连通 | 两个节点间有路径相连接 |
| 可达 | 从一个节点出发能够到达另一个节点 |
| 回路 | 从一个节点出发最后又回到该节点的一条路径 |
| 欧拉回路 | 经过图中每条边一次且仅一次的回路 |
| 欧拉图 | 存在欧拉回路的图 |
| 哈密尔顿回路 | 经过图中每个节点一次且仅一次的回路 |
| 哈密尔顿图 | 存在哈密尔顿回路的图 |

**一笔画规则**（`[补充]`，欧拉路径判定）：

1. 全是偶度点的连通图 → 可以一笔画成，起点和终点相同（欧拉回路）；
2. 只有两个奇度点、其余为偶度点的连通图 → 可以一笔画成，必须从一个奇度点出发、另一个奇度点结束（欧拉路径）；
3. 其余情况 → 不能一笔画出。

**课堂练习**：对任意一个有 $n$ 座桥的河道图，“走遍这 $n$ 座桥且只许走过每座桥一次最后又回到原出发点”的路径？

- A 一定存在不止一条路径；
- B 一定存在唯一路径；
- C 一定不存在这样的路径；
- D 可能存在，也可能不存在。

答案：**D**（取决于图的度数结构）。

### 2.4 TSP 问题：旅行商问题

**定义**：有若干个城市，任何两个城市之间的距离都是确定的；旅行商从某城市出发，必须经过每一个城市且只能在每个城市逗留一次，最后回到原出发城市。问如何确定一条最短路线，使旅行费用最少。

图论表述：在带权图中寻找一条**经过每个节点一次且仅一次的回路**（哈密尔顿回路），使总权值最小。

示例图（A、B、C、D 四城市）：

```
        B
     2 / \ 4
      /   \
     A-----C
      \5 6/ \
       \ /  2
        D
```

距离矩阵：

| | A | B | C | D |
|---|---:|---:|---:|---:|
| A | — | 2 | 6 | 5 |
| B | 2 | — | 4 | 4 |
| C | 6 | 4 | — | 2 |
| D | 5 | 4 | 2 | — |

### 2.5 TSP 的数学模型

输入：

- $n$ 个城市，记为 $V=\{v_1,v_2,\ldots,v_n\}$；
- 任意两个城市 $v_i,v_j$ 之间的距离 $d_{v_i v_j}$。

输出：

- 所有城市的一个访问顺序 $T=\{t_1,t_2,\ldots,t_n\}$，其中 $t_i \in V$，且 $t_{n+1}=t_1$；
- 使得：

$$
\min \sum_{i=1}^{n} d_{t_i t_{i+1}}
$$

求解思想：在所有可能的访问顺序 $T$ 构成的状态空间 $\Omega$ 上，搜索使总距离最小的 $T_{opt}$。

> `[补充]` 用整数给城市编号、用带下标的变量表示城市间距离，是“符号化”的关键一步：把现实问题变成可枚举、可计算的形式。

### 2.6 算法类问题

> **算法类问题**：由一个算法可以解决的问题；寻找一个（唯一的）方法（算法），以解决同一类型的无穷多个单个问题系列的问题。

同一模型的不同应用：

| 应用问题 | 表述 | 建模 |
|---|---|---|
| 配送路径规划 | $n$ 个地点送货，怎样次序使距离最短 | 城市 → 地点，距离 → $d_{ij}$ |
| 电路板钻孔路径规划 | $n$ 个位置钻孔，怎样次序使钻头移动最短 | 城市 → 孔位，距离 → $d_{ij}$ |
| 旅行商路径规划 | $n$ 个城市旅行，怎样次序使交通成本最低 | 城市 → 城市，距离/成本 → $d_{ij}$ |

结论：**现实问题抽象后可能是同一个算法类问题**（都是 TSP）。

## 3. 算法策略

### 3.1 算法策略是求解问题的一种思想

输入/输出/约束/目标四要素：

- **输入（已知）**：自然数表征对象，带下标的变量关联特性；
- **输出（可能解的形式）**；
- **约束**：满足约束的解是可行解；
- **目标**：满足目标的解是最优解（精确解）。

算法策略分两类：

| 目标 | 策略 | 例子 |
|---|---|---|
| 求精确解 | 遍历/枚举：数学计算—验证 | 遍历 TSP |
| 求可行解/近似解 | 贪心、启发式；以近似解换取计算量降低 | 贪心 TSP |

### 3.2 遍历算法（蛮干/枚举）

思路：列出每一条可供选择的路线，计算每条路线的总里程，最后选最短。

四城市示例的所有路径：

| 路径 | 总距离 |
|---|---:|
| A → B → C → D → A | 13 |
| A → B → D → C → A | 14 |
| A → C → B → D → A | 19 |
| A → C → D → B → A | 14 |
| A → D → C → B → A | 13 |
| A → D → B → C → A | 19 |

最优解：13。

### 3.3 组合爆炸

- $n$ 个城市的路径组合数：$(n-1)!$；
- 20 个城市：$19! \approx 1.216 \times 10^{17}$ 条路线；
- 计算机每秒检索 1000 万条路线，需要约 **386 年**。

> `[补充]` 这就是“组合爆炸”：问题规模稍大，枚举就不可行。TSP 的遍历算法复杂度是 $O((n-1)!)$。

幻灯片还给出一个真实案例：

- 2001 年解决德国 15112 个城市的 TSP 问题；
- 使用 110 台计算机（500 MHz Compaq EV6 Alpha），所有计算机花费时间之和为 **22.6 年**；
- 解是 43,589,145,600 条可能路线中最短的一条。

### 3.4 贪心算法

基本思想：“今朝有酒今朝醉”。

- 一定要做当前情况下的最好选择，否则将来可能会后悔，故名“贪心”；
- 从某个城市开始，每次选择一个城市，直到所有城市都被走完；
- 每次选择下一个城市时，只考虑当前情况，保证迄今为止经过的路径总距离最短（最近邻策略）。

四城市示例：从 A 出发，A-B=2、A-D=5、A-C=6 → 先选 B；从 B 出发，未访问的 C、D 距离都是 4 → 任选一个；可能得到：

```
A → B → C → D → A = 13（最优）
A → B → D → C → A = 14（非最优）
```

**贪心不一定得到最优解**，但速度快得多。

### 3.5 课堂练习

**练习 1**：关于贪心算法与遍历算法求解 TSP，下列说法正确的是？

- A 遍历算法比贪心算法快得多 —— 错误；
- B 遍历算法求出的解比贪心算法好得多 —— **正确**（遍历求精确最优解，贪心只求近似解）；
- C 遍历算法和贪心算法都是求精确解的算法 —— 错误；
- D 遍历算法和贪心算法都不能求出精确解 —— 错误。

答案：**B**。

**练习 2**：关于求解 TSP 的贪心算法，下列说法正确的是？

- A 贪心算法是速度最快的精确解算法 —— 错误；
- B 贪心算法求出的解一定是最优解 —— 错误；
- C 贪心算法求出的解不一定是问题的最优解 —— **正确**；
- D 贪心能求最优解但比遍历快得多 —— 错误。

答案：**C**。

**练习 3（背包问题填空）**：给定物品和背包容量 15 kg，贪心策略是“优先选择能装下的价格最高的盒子”，求总价值。

物品：

| 盒子 | 价格 | 重量 |
|---|---:|---:|
| 灰色 | 20 | 15 kg |
| 黄色 | 8 | 1 kg |
| 绿色 | 4 | 12 kg |
| 橙色 | 3 | 1 kg |
| 蓝色 | 2 | 2 kg |

贪心过程：

1. 价格最高的是 20，重量 15 kg，恰好能装下 → 选择它；
2. 背包已满，总价值 **20**。

答案：**20**。

> `[补充]` 此例中贪心恰好得到最优解；但贪心并不保证最优——如果最高价物品很重，可能会挤掉多个总价更高的轻物品。

### 3.6 精确解与近似解

- **精确解**：遍历所有可能解，验证后得到的最优解；
- **近似解**：用贪心等策略得到的可行解，不保证最优；
- 偏差：

$$
\Delta = |\text{近似解} - \text{精确解}|
$$

- **满意解**：$\Delta$ 充分小时的近似解。

## 4. 算法的表达：数据结构与控制结构

### 4.1 为什么需要数据结构

> **数据结构**：数据的逻辑结构、存储结构及其操作的总称，它提供了问题求解/算法的数据操纵机制。

两个层面：

- **逻辑结构**：数据元素之间的逻辑关系（如线性表、树、图）；
- **存储结构**：数据在内存中的表示（如数组、指针、地址）；
- **操作**：在结构上定义的操作（插入、删除、查找、遍历等）。

机器层面：

- CPU 能处理的数据必须保存在存储器中；
- 【存储单元】vs.【地址】；
- 算法层面：【变量】vs.【变量名】、【变量类型】。

### 4.2 变量与存储单元

高级语言：

- 用变量保存数据，变量名 vs. 变量值；
- 变量使用前要声明类型（如 `int`、`long int`、`char`）；
- 变量可以通过赋值改变值。

机器层面：

- 所有数据都保存在存储器中；
- 不同类型占用不同个数的存储单元，表示方法也可能不同；
- 一般 `int` 占 2 个存储单元，用二进制补码表示；
- `long int` 占 4 个存储单元；
- `char` 占 1 个存储单元，用 ASCII 码表示；
- 变量装入内存时，建立“变量名 ↔ 存储单元地址”的映射。

例：

```c
int X = 23;
char Y = 'A';
char Z = 'B';
```

内存示意：

```
地址        内容
00000000    00000000
...
X 的地址    00000000 00010111   （23）
Y 的地址    01000001            （'A' = 65）
Z 的地址    01000010            （'B' = 66）
```

> `[补充]` 变量名只是给人看的，机器只认地址；编译/链接后，变量名被替换成地址或寄存器编号。

### 4.3 指针

> **指针**：一种内存地址型变量，其存储的是一个内存地址，该地址对应的存储单元才是指针实际指向的值。

例：

```c
String *P = "ABCD";   // P 存的是字符串的地址
String v = "ABCD";    // v 存的是字符串本身
```

- `P` 的值是一个地址；
- `*P` 才是该地址对应的内容；
- 指针使数据结构可以动态连接（链表、树、图）。

### 4.4 典型数据结构：树

树的逻辑结构：

```
        100
       /   \
      50    ...
     /  \
    30  70
```

两种存储方法：

1. **父指针/子指针**：每个节点存储数据元素 + 指向子节点的指针；
2. **左/右指针（二叉树）**：每个节点存储数据元素 + 左孩子指针 + 右孩子指针。

```
存储地址    数据元素    左指针    右指针
...         100        ...       ...
...         50         ...       ...
...         30         ...       ...
```

> `[补充]` 数据结构的核心是“逻辑关系”与“存储表示”的分离：同一棵树可以用数组、父指针、左右指针等不同方式存储，只要逻辑关系保持一致。

### 4.5 TSP 问题中的数据表达

- 城市映射为编号：A→1，B→2，C→3，D→4；
- 城市间距离：二维数组 $D$，用 $D[i][j]$ 或 $D[i,j]$ 访问；
- 访问路径/解：一维数组 $S$，用 $S[j]$ 访问。

例：

```
距离矩阵 D：
    1  2  3  4
1   —  2  6  5
2   2  —  4  4
3   6  4  —  2
4   5  4  2  —

路径 S：[1, 4, 3, 2] 表示 A → D → C → B → A
```

### 4.6 算法的类自然语言表达

- 自然语言容易理解，但容易出现**二义性、不确定性**；
- 例：求 $1+2+\cdots+n$：

```
(1) 输入 N；
(2) i = 1，sum = 0；
(3) 如果 i ≤ N，执行第 (4) 步，否则转到第 (7) 步；
(4) sum = sum + i；
(5) i = i + 1；
(6) 返回第 (3) 步；
(7) 输出 sum。
```

### 4.7 流程图

基本符号：

| 符号 | 含义 |
|---|---|
| 矩形框 | 一组顺序执行的规则/语句 |
| 菱形框 | 条件判断，决定分支 |
| 圆形框/椭圆框 | 算法或程序的开始/结束 |
| 带箭头的线 | 程序的走向 |

三种基本控制结构：

1. **顺序结构**：执行 A，然后执行 B；
2. **分支结构**：如果条件 Q 成立，执行 A，否则执行 B；
3. **循环结构**：重复执行 A。
   - **有界循环**：执行 A 共 N 次；
   - **条件循环**（无界循环）：当条件 Q 成立时反复执行 A，直到 Q 不成立。

欧几里得算法流程图：

```
开始
  ↓
以 N 除 M，令余数为 R
  ↓
R ≠ 0?
 ├─ 是 → M = N，N = R → 回到“以 N 除 M”
 └─ 否 → 输出 N → 结束
```

> `[补充]` 流程图是算法与程序之间的桥梁：先画流程图，再翻译成高级语言，能减少逻辑错误。

### 4.8 TSP 遍历算法的表达

思路：

1. 当前最短路径 `MS` 设为空，当前最短距离 `DTemp` 设为最大值；
2. 枚举所有路径 `S[1..n]`；
3. 计算每条路径的距离：

$$
\text{Distance} = \sum_{i=1}^{n} D[S[i]][S[i+1]] + D[S[n]][S[1]]
$$

4. 如果 `Distance < DTemp`，更新 `MS` 和 `DTemp`；
5. 所有路径枚举完毕后，输出 `MS` 和 `DTemp`。

### 4.9 TSP 贪心算法的表达

- 依次访问过的城市编号记录在 `S[1], S[2], ..., S[N]` 中；
- `Step(1)`：从 1 号城市开始，`S[1] = 1`；
- `Step(5)`：从所有未访问过的城市中，查找距离当前城市 `S[I-1]` 最近的城市 `j`；
- `Step(6)`：`S[I] = j`；
- 重复直到所有城市访问完，最后加上回到起点的距离。

细化第 5 步：

```
(5.1) K = 2;
(5.2) Dtemp = 一个大数;
(5.3) L = 1;
(5.4) 如果 S[L] == K，转 5.8；   // 已访问，跳过
(5.5) L = L + 1;
(5.6) 如果 L < I，转 5.4;
(5.7) 如果 D[K][S[I-1]] < Dtemp，则 j = K，Dtemp = D[K][S[I-1]];
(5.8) K = K + 1;
(5.9) 如果 K <= N，转 5.3。
```

伪代码：

```
S[1] = 1; Sum = 0; I = 2;
while I <= N:
    从所有未访问城市中找距 S[I-1] 最近的 j
    S[I] = j
    Sum = Sum + D[j][S[I-1]]
    I = I + 1
Sum = Sum + D[S[N]][1]
输出 S 和 Sum
```

> `[补充]` 贪心算法的三重循环（找下一个城市、检查是否访问过、遍历城市编号）决定了它的复杂度为 $O(n^3)$；而遍历算法是 $O((n-1)!)$。

## 5. 算法复杂性与计算复杂性

### 5.1 算法的正确性

- 算法是正确的吗？
- 算法的输出是问题的解吗？
- 满足约束的解是**可行解**，但不一定是**最优解**；
- 20 世纪 60 年代，美国一架发往金星的航天飞机因控制程序出错而永久丢失在太空中——正确性至关重要。

评价方法：

1. **证明方法**：用数学方法证明算法正确；
2. **仿真分析方法**：产生大量有代表性的问题实例，运行算法，对结果进行统计分析。

### 5.2 算法效果评价

- 输出的是最优解还是可行解？
- 如果是可行解，与最优解的偏差多大？

TSP 贪心算法：

- 直观检查：输出中每个城市出现且仅出现一次 → 是可行解；
- 与最优解比较：小规模实例可求最优解；大规模实例最优解未知，只能与前人算法比较。

### 5.3 复杂度分析示例

```c
sum = 0;                      // 1 次
for (i = 1; i <= n; i++)      // n 次
{
    for (j = 1; j <= n; j++)  // n² 次
    {
        sum++;                // n² 次
    }
}
```

$$
T(n) = 2n^2 + n + 1 = O(n^2)
$$

主要关注点：**循环的层数、递归/迭代的次数**。

### 5.4 常见的复杂度量级

从小到大：

$$
O(1) < O(\log n) < O(n) < O(n\log n) < O(n^b) < O(b^n) < O(n!)
$$

| 量级 | 名称 | 典型例子 |
|---|---|---|
| $O(1)$ | 常数 | 数组按下标访问 |
| $O(\log n)$ | 对数 | 二分查找 |
| $O(n)$ | 线性 | 顺序查找 |
| $O(n\log n)$ | 线性对数 | 归并排序、快速排序（平均） |
| $O(n^b)$ | 多项式 | 双重/三重循环 |
| $O(b^n)$ | 指数 | 子集枚举 |
| $O(n!)$ | 阶乘 | 全排列、TSP 遍历 |

多项式时间算法（$O(1), O(\log n), O(n), O(n\log n), O(n^b)$）在大规模问题上通常可接受；指数/阶乘时间算法在 $n$ 较大时不可行。

例：$n=60$，每秒百万次：

- $O(n^3)$：约 0.2 秒；
- $O(3^n)$：约 $4 \times 10^{28}$ 秒 $\approx 10^{15}$ 年（相当于 10 亿台计算机计算一百万年）。

### 5.5 TSP 的两种复杂度

| 算法 | 策略 | 时间复杂度 | 解的质量 |
|---|---|---|---|
| 遍历算法 | 枚举所有路径 | $O((n-1)!)$ | 精确最优解 |
| 贪心算法 | 每次选最近的未访问城市 | $O(n^3)$ | 近似解，不保证最优 |

**课堂练习**：程序段

```c
sum = 0;
for (i = 1; i <= n; i++)
    for (j = 1; j <= n; j++)
        for (k = 1; k <= 20; k++)
            sum++;
```

时间复杂度是？

- 外层两重循环是 $O(n^2)$；
- 内层 $k$ 从 1 到 20，是常数次；
- 总复杂度 $O(n^2)$；
- 答案：**B**。

### 5.6 算法复杂性与计算复杂性

| 概念 | 定义 |
|---|---|
| **算法复杂性** | 求解问题的**某一个算法**的复杂性 |
| **计算复杂性** | 能求问题**精确解的那个最快算法**的复杂性；是问题本身的特性 |

TSP：

- 遍历算法复杂度：$O((n-1)!)$；
- 贪心算法复杂度：$O(n^3)$；
- TSP 的计算复杂性：$O((n-1)!)$（因为求精确解的最快已知算法是遍历类）。

### 5.7 可解性问题与难解性问题

- **可求解问题**：计算机在有限时间内能够求解；
- **难求解问题**：计算机在有限时间内不能求解；
- **不可计算问题**：计算机完全不能求解。

#### P 类问题

> **P 类问题**（Polynomial Problem）：计算机可以在多项式时间内求解的问题，即可以找出一个 $O(n^k)$ 复杂性的算法求出精确解的问题（$k$ 为常数）。

#### NP 类问题

> **NP 类问题**（Non-deterministic Polynomial）：在多项式时间内可以**验证**一个解是否正确的问题。

- 这类问题直接求精确解可能很难，但给定一个候选解，验证它是否正确可以在多项式时间内完成；
- $P \subseteq NP$。

#### NPC 类问题

> **NPC 类问题**（NP-Complete）：NP 类问题中最难的一类问题。

满足：

1. NP 问题的所有可能答案都可以在多项式时间内验证；
2. 求精确解只能遍历每一个可能解；
3. 遍历所有可能解的复杂性呈指数或阶乘级别。

#### NP-Hard

NP 难问题：至少和 NPC 问题一样难的问题；不一定属于 NP。

**开放问题**：$P = NP$？这是美国克雷数学研究所的百万美元大奖难题之一。

> `[补充]` 记忆方式：
>
> - P：**能快速解**；
> - NP：**能快速验证**；
> - NPC：NP 里**最难**的；
> - NP-Hard：**至少和 NPC 一样难**，可以不属于 NP。
>
> 加密算法通常希望设计成“验证容易、破解难”的问题（如大整数分解），这与 P/NP 的研究密切相关。

### 6.4 自测问题（附答案）

1. 算法与程序有什么区别？
   **答**：算法是求解问题的步骤，可以用自然语言、流程图、伪代码表达；程序是算法用某种计算机语言的具体实现，能被机器执行。
2. 算法的五个特征是什么？
   **答**：有穷性、确定性、输入、输出、能行性。
3. 为什么哥尼斯堡七桥问题无解？
   **答**：把陆地看成节点、桥看成边后，四个节点度数都是奇数；欧拉回路要求所有节点度数为偶数，因此不存在。
4. TSP 的遍历算法为什么不可行？
   **答**：路径组合数为 $(n-1)!$，随 $n$ 增长极快（20 个城市约 $1.216\times10^{17}$ 条），产生组合爆炸。
5. 贪心算法为什么不能保证最优？
   **答**：它每步只做当前最优选择，不考虑整体；局部最优的累积不一定是全局最优。
6. 数据结构包含哪三个层面？
   **答**：逻辑结构、存储结构、操作。
7. 算法复杂性和计算复杂性有什么区别？
   **答**：算法复杂性是某一个算法的复杂度；计算复杂性是问题本身（求精确解的最快算法）的复杂度。
8. P、NP、NPC 分别是什么？
   **答**：P 是多项式时间可解；NP 是多项式时间可验证；NPC 是 NP 中最难的一类问题。
